# 3-D solver leg -- TVC in `tensorsph.dam_break_3d`, and the front-metric frame fix

_Generated by `benchmarks/xval_sphinx_tvc/solver_leg.py` from `docs/xval_sphinx_tvc/data/solver_leg.json` (host: python 3.11.6, torch 2.7.1, git c7bbc5d2)._ 

## 1. What was missing

The dimension leg made the operator dimension aware and graded it on lattices; the physics leg ran the **2-D** dam break.  Neither touched the case the port's own motivation names, `tensorsph.dam_break_3d`: its `run_case` had no correction hook at all, and its front metric divided the *absolute* leading-edge coordinate by the column width, so every reported `Z/a` carried a constant offset of `1 - dx/(2a)` against the Ritter / Martin & Moyce frame (which measures distance travelled from the dam face).

Both are fixed here: `DamBreak3DConfig` gains `tvc_every` / `tvc_alpha` / `tvc_scope_tol` / `tvc_max_shift` (defaults keep the case bit-identical), `run_case` applies the ported operator with `dim` inferred from the cloud (3), and `DamBreak3DRun.dimensionless` subtracts the leading edge at `t = 0`.
