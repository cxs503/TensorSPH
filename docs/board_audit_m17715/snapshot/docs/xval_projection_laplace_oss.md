## ① Problem, and where the reference comes from

In *incompressible* (projection / ISPH) SPH the pressure is a Lagrange multiplier of
`div u = 0`, so the static Young-Laplace jump of a droplet is carried by the Poisson
source (the CSF traction) instead of by a Tait equation of state. Here
`dp_measured = <p>_core - <p>_band` is compared with the analytic 2-D law `dp = sigma/R`
(circle: curvatures `1/R`, `0`); `R = 0.02 m`, `sigma = 0.072 N/m`, `rho0 = 1000 kg/m^3`,
`dp_theory = 3.6000 Pa`.

**Reference implementation (OSS).** PySPH `1.0b3.dev0` (`pypr/pysph`), installed read-only
at `/tmp/xv2/lib64/python3.11/site-packages/pysph`. Two pieces are the reference algorithm:

* incompressible scheme — `pysph/sph/isph/isph.py:121` (`VelocityDivergence`, the projection
  source), `:157` (`PressureCoeffMatrix`, the pressure operator), `:190` (`PPESolve`,
  scipy sparse + `bicgstab`);
* surface tension — `pysph/sph/surface_tension.py:314` (`SmoothedColor`), `:336`
  (`ColorGradientUsingNumberDensity`, SY11 eq 13), `:565` (`SY11DiracDelta`, SY11 eq 14),
  `:620` (`InterfaceCurvatureFromNumberDensity` + Morris eq 22-23 correction), `:708`
  (`CSFSurfaceTensionForce`, JM00 eq 25).

Kernel identity was checked first, not assumed: PySPH `CubicSpline` 2-D normalisation
(`pysph/base/kernels.py:29`, `sigma_3 = 10/(7 pi h^2)`) reproduces this repo's
`cubic_spline_kernel` to the last printed digit at `r/h = 0, 0.3, 1.0, 1.7`
(`W = 2.690701e+03, 2.381943e+03, 6.726752e+02, 1.816223e+01` both sides).

## ② Method

Both arms run on **the same particle lattice, same kernel, same `h/dx`, same pressure
gauge** (`p = 0` on the outer 1.6 dx layer of the block), so the residual difference is the
interface/projection discretisation only.

* **ours** (`tensorsph.laplace_isph.laplace_isph_case`): Shepard-smoothed colour ->
  first-order-consistent MLS gradient -> interface normal smoothed twice -> curvature
  `div n` in MLS form (`mls`) -> Brackbill delta `|grad c|` -> CSF acceleration
  `a = -sigma kappa delta n/rho` -> Cummins & Rudman pair Laplacian
  `sum_j 2 V_j (p_i-p_j)(r.grad W)/(r^2+eta^2)`, matrix-free Jacobi-CG (`rel_tol 1e-10`).
* **oss** (`tensorsph.oss_projection`): `SmoothedColor` (unnormalised kernel sum, self term included) ->
  SY11 colour gradient with number density -> SY11 curvature with Morris correction ->
  `a = sigma kappa grad C / rho` -> `PressureCoeffMatrix` operator
  `fac_ij = 8 m_j/(rho_i+rho_j)^2 (XIJ.DWIJ)/(R2IJ+EPS)`, same gauge, same CG tolerance.

Two forms of the number-density factor are measured, because the reference **code** and the
reference **docstring** disagree (see §⑤/§⑥): `psiab1 = 2/(V_i+V_j)` as shipped
(`form="code"`) and the paper-consistent `2/(psi_i+psi_j) = 2 V_i V_j/(V_i+V_j)`
(`form="paper"`, `psi = 1/V`).

### Manufactured Poisson check

The reference pressure operator on `p = rho r^2/4` (unit source) gives a relative error
of 1.45 at R/dx = 10 on a 3.2 cm block — the operator is not a converged Laplacian at
that block size; it is reported, not used as a gate.

## ⑤ Difference list: this repo vs OSS (做法 / 参数 / 边界条件) and the porting trade-off

| # | aspect | TensorSPH (ours) | PySPH reference | ported? |
|---|---|---|---|---|
| 1 | colour field | Shepard-normalised indicator, `c = sum V W c / sum V W` | unnormalised kernel sum `sum V_j c_j W_ij` (JM00 eq 17) | no — normalisation kept; the unnormalised sum saturates with the self term and is only defined up to the lattice (`SmoothedColor` 2.7e3 W(0) * V) |
| 2 | colour gradient | first-order-consistent MLS (matrix inversion per particle) | kernel difference with number-density weight (SY11 eq 13) | **yes** (as the "oss" arm) |
| 3 | curvature | `div n` in MLS form (default) or local quadratic fit (option) | `sum 2/(psi_i+psi_j)(n_i-n_j).grad W` + Morris `sum V W` correction | **yes** |
| 4 | Dirac delta | `|grad c|` (Brackbill), Shepard-consistent | `|grad C|` (SY11 eq 14); the shipped force folds it into `grad C` | yes, and the fold is kept |
| 5 | surface force | `a = -sigma kappa delta n/rho` | `a = sigma kappa grad C/rho` | matrix-identical once `n = -grad c/|grad c|` |
| 6 | pressure operator | `sum 2 V_j (p_i-p_j)(r.grad W)/(r^2+eta^2)`, `eta = 0.1h`, `rho0` constant | `8 m_j/(rho_i+rho_j)^2 (XIJ.DWIJ)/(R2IJ+EPS)`, `EPS = 0.01 h^2` measured, variable `rho` | **yes** (both give `~ (1/rho) lap p`; ours absorbs `rho0`) |
| 7 | Poisson source | `-rho div a` with MLS divergence | `div u/dt` with SPH divergence `-sum V_j (u_i-u_j).grad W` | **yes** (the `dt` cancels in the static limit) |
| 8 | pressure BC | Dirichlet `p = 0` on the outer block layer | free-surface `p = 0` where the density deficit is, walls Neumann/mirror (`isph.py:280`, `:294`) | **no** — the droplet carrier has no free surface and no wall inside the block; a common gauge is required to compare, so both arms use the outer Dirichlet layer (documented deviation) |
| 9 | solver | matrix-free Jacobi-CG, `rel_tol 1e-10` | assembled scipy sparse + `bicgstab` | **no** — solver accuracy is not the object of comparison; ours is the tighter one |
| 10 | time integration | static equilibrium (one Poisson solve) | `ISPHStep`/`SISPHStep` with δ-ISPH density-invariance terms | **no** — the case is a static verification; the OSS time loop is not exercised |

**Porting trade-off (why not a blind transplant).** Rows 1, 8, 9, 10 were deliberately *not*
ported: the unnormalised colour sum couples the answer to the lattice normalisation; the
free-surface BC has no meaning in a filled carrier and would inject a second gauge; the
sparse/bicgstab solver would add an iterative-error term to a 3 % measurement; and the
δ-ISPH time loop would test a different question. Rows 2-7 *were* ported because they are
the physics under test, and taking them over changed the answer: the reference route is
`+3 %` biased where ours is `−0.2 %`, and the reference's own shipped number-density
normalisation destroys the jump entirely, so the transplant is only usable with the
paper-consistent `2/(psi_i+psi_j)` (row 3/5 dependency). Everything the transplant gained
(divergence-of-normals curvature with the Morris correction, and the `(1/rho)`-weighted
pressure operator) is expressible in this repo without new dependencies; it is left as a
candidate operator rather than switched on, because it is 3 % biased *and* 2x more
expensive per level than the shipped MLS route.
