## ① 为什么这是增量，而不是又一次重做

前七轮把**判据脚本**（`ensemble_peak.py` / `ladder_closure.py`）当成可信的度量工具，
只在**数据侧**加网格、加帧、加参考。本轮反过来审**工具本身**，发现两个自相矛盾的记录
（全部来自已提交工件，不是新算）：

| 网格 | 工件里 `by_frames.61.judgeable` | 同一记录里的 `jackknife_rel` | `ladder_closure` 的结论 |
|---|---|---|---|
| dx=4mm | False | 0.12 % | 不可判 |
| **dx=2mm** | **True** | **42.95 %**（early 8.208 / late 5.742） | **不可判** |
| **dx=1mm** | **False** | 6.48 % | **可判** |
| dx=0.5mm | False | 20.90 % | 不可判 |

一个网格"可判"与否，在同目录的两个模块里给出**相反**答案（dx=2mm 与 dx=1mm 各一处）。
更糟的是：`judgeable` 由**产出工件**的模块写，`ladder_closure` 由**下游**模块读——
所以假阳性会顺着数据流走。这就是本单要查的东西：`judgeable` 的定义是
`spread over full bin grid < 15 %`，它同时（a）不用分辨率带、（b）忽略半窗分裂；
而 `ladder_closure` 用的是 `max(band, jackknife)`。前者在 dx=1mm 上过严（0.140>0.15），
在 dx=2mm 上过松（0.140<0.15 而 jackknife 43 %）。

**这不是风格问题**：按 15 % 门槛，dx=2mm 的读数 6.071 对指定参考 6.92 只差 −12.27 %，
一旦被判为"可判"，闭合法则（≥2 个同号可判网格）立刻满足，锚点会被**误闭合**。

## ② 怎么做的（方法/流程/工具链）

1. **从帧级数据重建同一问题**（`frame_stationarity.py`，只读工件，无求解器）：
   工件的 `frame_scan` 存了每帧 `n_wet`、单帧点峰 `cp_peak_single_frame`、峰位 `tau_at_peak`。
   在帧级重算半窗分裂是**独立于池化路线**的第二条口径。
2. **拆开共线**（`half_split_decomposition.py`，重跑同一轨迹，dx=2mm 本机 45 s、dx=4mm 11 s，
   均 <8 核 / <10 min）：对每个**可采信的 bin 数**分别算两半的池化读数，
   若两半在同一 bin 数下仍然分裂，则分裂不可能来自"两半的可采信 bin 集不同"。
3. **换一条不确定度口径**：对 61 帧做**帧 bootstrap**（有放回重采样 200 次，固定种子
   20261115），每次按分辨率带规则读数——它不需要把窗口切成两半。
4. **湿节点分层**：只在 `n_wet ≥ 16 / ≥ 30` 的子窗上读数，检验分裂是否只是"早期帧节点少"。
5. **可复现性门槛**：重跑的 legacy 半窗读数必须与已提交工件**逐位一致**，
   否则下面所有数字都不成立（实测一致到 1e-15，见 ③-a）。

dx=1mm 的同表（`halfsplit_dx0.001.json`，wall 287.9 s，分辨率带 16/20/30，读数 6.805、带散度 3.16 %，
与已提交工件逐位一致）：

| bin 数 | 6 | 8 | 10 | 12 | 16 | 20 | 30 |
|---|---|---|---|---|---|---|---|
| dx=1mm 分裂 | 4.7 % | 0.5 % | 5.7 % | 9.3 % | 6.5 % | 6.1 % | 11.6 % |

方向与 dx=2mm **相反**（dx=1mm：early 6.415 < late 6.860，读数随时间**上升**；
dx=2mm：early 8.208 > late 5.742，随时间**下降**），且幅度小一个量级。

→ 在**每一个**可采信 bin 数下，dx=2mm 的 early 半窗都高于 late 半窗，
且 bin 越细分裂越大（尖峰被更细的 bin 抓到，早期帧的高值被放大）。
**分裂不是 bin 组成的产物**，而是"窗口内读数随时间下降"这一真实非平稳性。
dx=4mm 的分裂在 bin 间剧烈跳动（2.2 %–51.7 %）且无方向，符合"节点太少（平均 13.7 个）、
bin 采信在噪声里跳"——粗网格给出的是噪声，不是趋势。

### (c) 帧级口径、bootstrap 与湿节点分层

| 网格 | 帧级早/晚分裂 | 帧 bootstrap 中位 | bootstrap 相对 sd | p05–p95 | `U = max(band, half)` | 判定 |
|---|---|---|---|---|---|---|
| dx=4mm | 8.7 % | 9.904 | 20.4 % | 7.14–13.70 | 23.5 % | 不可判 |
| dx=2mm | 2.7 % | 6.570 | 9.6 % | 5.66–7.64 | **43.0 %** | 不可判 |
| **dx=1mm** | 9.7 % | **7.076** | **12.6 %** | **5.97–9.02** | 6.5 %（工件口径） | **不可判（见下）** |
| dx=0.5mm | 17.3 % | —（cj4203 在队列） | — | — | 20.9 %（工件） | 不可判 |

**`dx=1mm` 是全案的枢轴，而它的 bootstrap 击穿了"可判"**：工件口径的半窗分裂只有 6.48 %，
分辨率带散度 3.16 %，于是 `ladder_closure` 判它可判、残差 −1.66 %、记为 PASS。
但同一批 61 帧的帧 bootstrap（固定种子、同一算子、只是有放回重采样）给出
中位 7.076、相对 sd 12.6 %、p05–p95 = 5.97–9.02（跨度约中位的 45 %）。
即：**把"窗口里有哪些帧"当成抽样自由度时，这个读数的 15 % 门槛根本进不去**，
而半窗分裂之所以只有 6.5 %，是因为它只用了"前后两半"这 1 个自由度。
→ 按帧抽样口径，dx=1mm **不可判**，全案 4 个网格**无一可判**。

湿节点分层（dx=2mm）：`n_wet≥16`（44 帧）读数 6.049、带内散度 13.6 %；
`n_wet≥30`（31 帧）读数 **5.812**、散度 10.5 %。即**去掉早期少节点帧后读数继续下降**，
与 (b) 的方向一致：池化 61 帧的 6.071 是**早期高值抬起来的**，不是收敛值。

两条口径不一致（dx=2mm：池化 43 % vs 帧级 2.7 %）不是矛盾，而是**它们测的不是同一个量**：
池化路线在两半上各自通过"bin 采信 + 中位"运算，早期半窗的样本稀疏让粗 bin 与细 bin 给出
差别很大的峰；帧级中位只看每帧的点峰。**结论必须两边都说**：状态量（池化读数）随窗口漂移
35 %–76 %，而单帧点峰的分布中位只漂移 2.7 %——漂移住在"峰的空间分布"里，不在"每帧的最大值"里。

## ⑤ 注意点（不粉饰）

1. **`dx=0.5mm` 的分解仍未取回**：`cj4203` 写作时在队列。`dx=1mm` 的 `cj4202` 已在收尾前返回
   （`halfsplit_dx0.001.json`，见 ③-b/③-c），因此本单对 4/2/1 mm 三个网格有证据，
   **`dx=0.5mm` 记 `WITHHELD`**。
2. **帧级 2.7 % 与池化 43 % 的口径差异本身是一个待解释的物理问题**：单帧点峰（极大值统计量）
   几乎不漂，而池化剖面峰漂 43 %，说明变化发生在剖面形状上（喷溅根部 vs 驻点区的相对权重），
   本单只做到"证明它不是 bin 组成的产物"，**没有定位到形状演化的物理原因**。
3. **bootstrap 中位（6.570）与点读数（6.071）差 8 %**：有放回重采样会重复样本、改变每 bin
   的样本数，从而改变"采信 bin 集"。这说明该估计量对**样本密度**不中性——另一条未修的脆弱性，
   本单只记录不修。
4. **湿节点门限 16 是预先声明**（见模块 docstring 的规则段），不是挑出来让结论好看；
   它对 dx=2mm 的作用是把读数**推低**（5.81），把残差从 −12 % 推到 −16 %，即**对算例不利**。
5. **本单没有推翻任何已提交的*数字***，推翻的是"这些数字可判 / 可闭合"的**解释**：
   工件里的 6.071、6.805、10.041、8.984 逐位可复现。
6. **不给"应当闭合"的替代判据**：现在缺的是"窗口无关的估计量"，不是新阈值。
   在它出现之前，任何把 dx=1mm 的 −1.66 % 记成 solver accuracy 的说法都是**窗口选择的产物**。

## ⑥ 误差判定（逐项，显式回答是否 < 3 %）

| 量 | 基准 | 结果 | 偏差 | < 3 % ? |
|---|---|---|---|---|
| dx=2mm 重跑分辨率带读数 | 已提交工件 6.070821 | 6.070821 | 0 % | **是** |
| dx=2mm 重跑 early/late 半窗 | 工件 8.208 / 5.742 | 逐位相同 | 0 % | **是** |
| dx=4mm 重跑读数与半窗 | 工件 10.041 / 10.053 | 逐位相同 | 0 % | **是** |
| dx=4mm 半窗分裂随 bin 数的稳定性 | 自身（同一半窗、换 bin） | 2.2 %–51.7 % | 最大 49.5 pp | **否**（粗网格读数不可判） |
| dx=2mm 帧级半窗分裂 vs 池化半窗分裂 | 池化 43.0 % | 帧级 2.7 % | 40.3 pp 口径差 | **否**（两条口径不一致，故两个都报） |
| dx=1mm 漂移方向 | dx=2mm 方向（向下） | **反向**（向上，early 6.415 / late 6.860，各 bin 数同向） | 符号相反 | **否**（两网格不同号 → 闭合法则不可能由它们满足） |
| dx=1mm 读数不确定性（帧抽样） | 工件口径 6.48 % 半窗分裂 | bootstrap p05–p95 = 5.97–9.02，相对 sd 12.6 % | 相对跨度 45 % | **否**（>15 % 门槛） |
| dx=0.5mm 漂移方向 | — | **未取回**（cj4203 队列中） | — | **无基准，不可判（WITHHELD）** |

**回答「是否 <3 %」**：
* **可复现性层面：是**（重跑与已提交工件逐位一致，0 %）——本单所有差异都不是数值噪声或版本漂移；
* **判据可靠性层面：否**——同一网格的"可判"结论在两个模块间相差一个量级（6.5 % vs 43 %），
  且池化读数随窗口漂移 35 %–76 %。因此本单**不支持**把 dx=1mm 的 −1.66 % 当作求解器精度，
  锚点维持 `open` / `NOT_DECIDABLE`，原因是**估计量非平稳 + 帧抽样不确定度超门槛**（结构性），而不是算力不足。
  4 个网格在"帧抽样"口径下**无一可判**，且 dx=1mm 与 dx=2mm 的漂移**反号**——闭合法则要求的
  "≥2 个同号可判网格"在当前估计量下不可能满足。

## ⑧ 给下一次自找活的线索（按价值排序）

1. **取回 cj4203（dx=0.5mm）的 `DECOMP` 行**：0.5mm 是唯一还没做分解的网格，
   而它的工件读数 8.984 是全梯子最高的——它的漂移方向决定"8.984 是噪声还是真反弹"。
2. **把估计量改成窗口无关量**：建议直接报**帧级点峰的分布量**（中位 + IQR）并配同算子解析场，
   理由是它在本轮里分裂只有 2.7 %（dx=2mm）且 bootstrap 口径明确；这需要重新对 COM 6.92 定标，
   不是改门槛。
3. **修 `ensemble_peak.judgeable` 的语义**：本单已加 `judgeable_stationarity` / `uncertainty_declared`
   两个新字段（旧字段保留以便工件可复现），下一步应在重生成工件时删除旧字段，避免下游再误读。
