# PR #185 (`agent/m3912`) CI red — root cause, one-byte fix, evidence

Mission m4372 · repository TensorSPH · PR #185 · branch `agent/m3912`

## 1. Symptom

PR #185 reported three identical failures: `pytest (3.10)`, `pytest (3.11)`,
`pytest (3.12)`. Identical failure across *all* interpreter versions rules out
anything version- or float-specific and points at a step that runs before the
tests in the same job.

## 2. Root cause (measured, not guessed)

`.github/workflows/tests.yml` runs, inside a **single job** named `pytest`:

1. `python -m ruff check .`   ← *Lint*
2. `python -m pytest -q`
3. … 11 more smoke/benchmark/negative-control steps

Step 1 fails → the job fails → the matrix reports `pytest (3.10/3.11/3.12) =
failure` **without a single test being executed**. Reproduced in this container:

```
$ git show HEAD:docs/merge_pr110_evidence/post_report.py > /tmp/red/post_report.py
$ python -m ruff check /tmp/red/post_report.py
W292 [*] No newline at end of file
  --> /tmp/red/post_report.py:69:11
Found 1 error.        (rc=1)
```

The file was added by the previous heal commit `05dc2ab` ("reproducible report
publisher for the merge evidence") and committed without a trailing newline.
`pyproject.toml` selects `["E","F","W"]`, so `W292` is inside the repository's
deliberate "correctness-only" gate. Three Python versions → three red jobs →
one 1-byte defect.

## 3. Fix

Exactly one byte in one file:

```diff
--- a/docs/merge_pr110_evidence/post_report.py
+++ b/docs/merge_pr110_evidence/post_report.py
@@ (end of file)
-    main()
+    main()
+                       (trailing newline added)
```

```
$ python -m ruff check .
All checks passed!
```

No solver, test, workflow or benchmark file is touched: the PR's own content is
otherwise unchanged, so the merge cannot move any scientific baseline.

### 4.3 pytest — 363 passed, 8 xfailed, **2 XPASS(strict) on loong64**

```
2 failed, 363 passed, 8 xfailed, 3 warnings in 315.37s
FAILED tests/test_oscillating_droplet.py::test_recorded_mode2_frequency_deficiency_is_reproduced
FAILED tests/test_oscillating_droplet.py::test_oscillation_frequency_gate_is_not_met
```

Both failures are `[XPASS(strict)]`, **not** assertion errors from the physics.
They are a property of *this* architecture, proven mechanically by
`mode2_arch_semantics.py` (output: `mode2_arch_semantics.json`), which evaluates
the two test bodies against both measurements recorded in the tests' own
`xfail` marker:

| architecture | mode-2 error | assertion | verdict under `strict=True` |
|---|---|---|---|
| x86_64 (GitHub runner) | +8.64 % | fails | XFAIL → job **green** |
| loongarch64 (this container) | −31.78 % | holds | XPASS → job **red** |

The two tests are written to fail when the 15 % gate is *met*; on the GitHub
runner (+8.64 %, gate met) they therefore xfail as intended. The pin and the
`strict=True` markers are **left untouched** by this fix — re-baselining the
architecture-fragile mode-2 fit is an open physics item (the documented verdict
stays FAIL: −43.5 % at R = 2 cm), out of scope for a CI-red heal, and changing
it would be exactly the kind of unrelated edit this mission forbids.

## 5. Hand-off (push is sandboxed)

`git push` and `github.com:443` are both blocked from the agent container, so
the commit is handed to the platform pusher. The pusher publishes the worktree
diff onto the current `main` tip as branch `agent/m<mission>`, and its
`_ruff_gate` pre-check re-runs `ruff` on the changed `.py` files.

To place the very same tree on the PR's own head instead, only a fast-forward
of `refs/heads/agent/m3912` is needed (idempotent, no force, no rewrite):

```bash
git merge-base --is-ancestor 05dc2ab <FIX_SHA>        # the PR head is an ancestor
git push origin <FIX_SHA>:refs/heads/agent/m3912      # fast-forward, PR #185 head
```

`<FIX_SHA>` is the single commit that adds this directory and the trailing
newline; the diff against `05dc2ab` is `docs/merge_pr110_evidence/post_report.py`
(+1 byte) plus `docs/pr185_ci_heal/` (evidence only).

## 6. Limitations / honest notes

* The two loong64 XPASS failures remain red **locally** by design; they are
  xfail-green on the x86_64 runner. A future CI addition of a loong64 job would
  resurrect them — that is the re-baseline item already recorded in the test.
* The three long physics CI steps were not replayed here (see 4.2); their code
  paths are untouched by this PR.
* Local pytest numbers come from the same tree modulo the one-byte fix; the
  fix cannot influence any test because no test imports a `docs/` script.
