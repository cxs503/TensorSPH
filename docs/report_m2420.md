## ① 案例介绍

### 物理/工程背景

TensorSPH 是基于 PyTorch 的 SPH（光滑粒子流体动力学）研究求解器，其 CI 流水线
承担三重门禁职责：

1. **Lint 门禁**（`python -m ruff check .`）：代码质量基线，先于 pytest 运行，
   一红则整条流水线（含全部单测）不给出结论。
2. **pytest 矩阵**（Python 3.10 / 3.11 / 3.12）：功能正确性回归。
3. **端到端验证**（droplet impact 2D + benchmark 对比）：物理验收。

### 问题描述

`main` 分支 CI 全红：

| 症状 | 详情 |
|---|---|
| Lint 步 | GitHub Actions run `41588768099`，`ruff check .` 报 **175 errors** |
| pytest 矩阵 | 3.10 / 3.11 / 3.12 三版本全挂（被 lint 阻断或自身失败） |
| 提交卫生 | 30 次提交中有 **11 次**带滤除标记（门禁滤除/工件不合规） |

### 仓库配置

```toml
[tool.ruff]
line-length = 100
target-version = "py310"
exclude = [".scratch"]

[tool.ruff.lint]
select = ["E", "F", "W"]   # pyflakes + pycodestyle，不含格式化

[tool.ruff.lint.per-file-ignores]
"benchmarks/**/make_doc.py" = ["E501"]   # CJK 长行豁免
"docs/reports/*_make_report.py" = ["E501"]
```

## ② 怎么做的

### 方法/流程

本单属 CI 基线修复类任务，遵循 TensorSPH 仓库已建立的 CI 清障模式
（先例：m3804 → m3805 → m4685 → m4814 → m4826）：

1. **本地复现 lint 违规全清单**
   - 在工作树执行 `python -m ruff check .`，按文件/规则分类统计。
   - 对照 CI 的 ruff 版本（`>=0.6`，CI 解析到 0.17.x）确认规则集一致。

2. **修复全部 lint 违规（不改语义）**
   - **E501**（行过长）：在已有空格处拆分为隐式字符串拼接，CJK 文本按列计数不变。
   - **F401**（未用导入）：删除。
   - **F841**（未用局部变量）：确认值确实未引用后删除。
   - **W292**（文件尾缺换行）：补换行。
   - **E401/E701/E702**（语句格式）：拆分或重排。
   - 每个文件修改后用 `ast.parse` 验证语法不变。

3. **lint 过后全量 pytest**
   - `python -m pytest -q` 跑完整测试套件。
   - 暴露的孤儿红（非 lint 引起的测试失败）按「工作树打捞法」处置
     （参考 TensorBEM m2228 孤儿打捞先例）：
     - 真 bug → 修复并记录。
     - 物理欠账（模型精度未达 15% 门限）→ `xfail(strict=False)` + 文档标注。
     - 工件缺失 → 改为从已提交数字重算并断言可复现。
     - 钉子值误转录 → 修正为实测值并标注来源。

4. **提交卫生清理**
   - 11/30 滤除标记的提交：检查工件是否超 200 KB 帽、是否含二进制、
     是否与 `.gitignore` 冲突，逐项处置。

## ⑤ 注意点

### 踩过的坑

1. **ruff 版本差异**：本地 ruff（0.15.x）与 CI ruff（0.17.x）的规则严格度
   不同，本地 0 errors 不代表 CI 也 0 errors。本单以 CI 版本为准。

2. **E501 与 CJK 文本**：`benchmarks/**/make_doc.py` 和 `docs/reports/*_make_doc.py`
   生成中文 markdown/LaTeX 表格，100 列上限对 CJK 无意义。已通过
   `per-file-ignores` 精确豁免 E501（仅 E501，F/W 继续生效），避免整棵
   benchmark 树被摘出 lint 范围。

3. **`.scratch/` 目录的传染性**：agent 的临时脚本若含未用导入，会让全仓
   所有 PR 的 CI 变红（m3804 的教训）。已通过 `exclude = [".scratch"]` +
   `.gitignore` 双重隔离。

4. **孤儿红的分类处置**：lint 清零后暴露的测试失败不能一刀切——
   - 物理欠账（如 Laplace 压强跳变 15% 门限未达）不能靠调参变绿，
     必须 `xfail(strict=False)` + 文档标注。
   - 钉子值误转录（如 0.79 → 0.711）需溯源到具体 harness 的分辨率/晶格类型。
   - 工件缺失的测试应改为「从已提交数字可复现」而非「文件存在」。

### 局限

1. **工件未保留**：原单交付时未将 lint 违规清单、pytest 输出日志等工件
   存入 `docs/` 或 `artifacts/` 目录，导致补报只能依据原单声明的汇总数字，
   无法提供按文件/规则的细粒度分布。
2. **未重跑验证**：补报阶段未重新执行 lint/pytest（工作树可能已与原单交付时
   的 main 有差异），结果数字完全依赖原单声明。
3. **11/30 滤除标记的具体处置**：每个提交的滤除原因和修复方式未留档。

### 适用范围

本单的修复模式（lint 清零 → pytest 孤儿分类处置 → 提交卫生清理）适用于
TensorSPH 仓库的任何 CI 基线修复场景。关键原则：
- **不改语义**：lint 修复只动格式/导入/死代码，不碰物理逻辑。
- **不为绿而绿**：测试失败若是物理欠账，如实标注而非降判据。
- **豁免要窄**：`per-file-ignores` 精确到文件和规则，防止豁免扩散。
