# Engineering review, 2026-10

This document records the measurements that motivated version 0.2.0. Every number below was
produced by running the code in this repository; the commands are given so they can be
re-run.

## 1. How the review was done

```bash
python -m venv .venv && .venv/bin/pip install -e ".[test]"
.venv/bin/python -m pytest -q                       # 30 tests before the fix
.venv/bin/python examples/droplet_impact_2d/run.py --steps 100
.venv/bin/python benchmarks/neighbor_search/compare.py --particles 1000
.venv/bin/python benchmarks/neighbor_search/compare_rhs.py --sizes 256,512,1024
```

Plus a 4600-step version of the impact case (46 s CPU) and ad-hoc probes of the initial
state, which are reproduced as the checks below.

## 2. Finding: the free surface produced tensile pressure

At `t = 0`, before a single integration step:

```
rho:       580 – 1000 kg/m^3        (42 % density deficit at the free surface)
pressure:  min -55.9 kPa, max -21 Pa, 100 % of particles negative
|acc|:     max 4405 m/s^2           (450 g)
```

Density summation under-counts neighbours at a free surface. The Tait law
`p = rho0 c0^2 / gamma * ((rho/rho0)^gamma - 1)` then returns a large negative pressure,
which in SPH acts as attraction. Reassembling the pressure-acceleration term outside the
repository with `p` clamped at zero reduced the maximum initial acceleration from
**4405 m/s^2 to 0**, i.e. the entire initial motion was spurious.

Consequences over 4600 steps (t = 0.092 s):

| metric | measured | physical expectation |
|---|---|---|
| nearest-neighbour distance | mean 0.0090 m, 70.6 % below dx/2, min 0.0 | ~dx = 0.025 m |
| `rho_max` | 1193 kg/m^3 (+19 %) | < 1 % for WCSPH |
| max speed | 22.5 m/s | 0.9 m/s free fall |
| kinetic energy | 2373 J | ~12 J available from the drop's potential energy |

Snapshot images show the lattice disintegrating by t = 0.01 s. The run *succeeded*: no
non-finite values, and the acoustic Courant number never exceeded 0.026.

## 3. Finding: the default case never reached the pool

`dt = 2e-5 s` with `steps = 500` covers 0.01 s, during which the drop falls 0.49 mm. The
discretised gap between the drop's lowest row (y = 0.415) and the pool surface (y = 0.3375)
is 0.0775 m, i.e. about 0.13 s of free fall — roughly 6500 steps. The "first milestone" case
therefore never performed an impact at default settings.

The time step was also 24x smaller than the acoustic limit required
(`0.3 h / c0 = 4.9e-4 s`).

## 4. Finding: the coordinate clamp was not a boundary condition

```python
pos[:, 1].clamp_(min=0.5*dx, max=pool_depth + 2*drop_radius)   # ceiling = 0.55 m
```

The drop's nominal top is `drop_center_y + drop_radius = 0.59 m`, so the ceiling amputated
part of the drop: 6 particles started above it and were teleported down on the first step.

Measured with `benchmarks/hydrostatic/run.py --seconds 4`:

| boundary | interior pressure error | residual max speed | particles clamped |
|---|---|---|---|
| coordinate clamp | **26.7 %** | 21.1 m/s | 1955 |
| static wall particles | **0.63 %** | 0.055 m/s | 0 |

Clamping positions without touching velocity also injects and removes momentum arbitrarily,
and coincident particles appeared in the static pool (minimum pair separation 0.000 dx).

The difference also shows up on the impact case. With `boundary="wall"` the default 750-step
run measures 2.2 % density compression, Mach 0.075, and zero clamped particles. The same
case with `boundary="clamp"` violates its own gates within 100 steps (5.1 % density
compression, Mach 0.162), which is why the clamp is retained only as an explicit, documented
regression baseline.

## 5. Finding: the manifest did not implement its own contract

`docs/algorithm-gap-analysis.md` required source revision, Python/PyTorch versions, three
separate statuses, and per-criterion thresholds. The manifest contained
`case/status/device/initial_particle_count/config/notes`. Documentation described a contract
that the code did not implement.

## 6. Finding: dependency coupling to NumPy's C ABI

`run()` called `pos.cpu().numpy()`. With `torch==2.2.2` and NumPy 2.x this raises
`RuntimeError: Numpy is not available` and two tests fail. Snapshots now hold tensors and
plots use `.tolist()`, so the solver no longer touches NumPy's ABI; the suite passes with
both NumPy 1.26 and 2.4.

## 7. Finding: dead configuration surface

- `make_particles` returned a `fixed` mask that `run` unpacked and never used.
- `Config.seed` plus `torch.manual_seed` did nothing: the case is a deterministic lattice
  with no stochastic step. The seed was removed rather than left as a misleading knob.
- `docs/` still listed the neighbour search as an open P1 item after it had been merged, and
  the manifest notes still described all-pairs interactions as the active implementation.

## 8. What was changed in 0.2.0

| area | change |
|---|---|
| EOS | `tait_pressure` clamps at zero; documented as a free-surface treatment, not capillary physics |
| time step | default 4e-4 s; `validate_config` rejects steps above `max_courant`; `suggested_dt` exposes the limit |
| boundary | `wall_lattice` static particles with Adami pressure extrapolation and Tait-consistent density; free-slip viscosity; `boundary_box` derives the ceiling from the drop geometry |
| acceptance | `evaluate_acceptance` + `SimulationUnstableError`; five numerical criteria recorded per run |
| manifest | solver revision, environment, three statuses, per-criterion measured/threshold/result, derived quantities |
| diagnostics | added `mach_number`; plot subsamples long runs and no longer converts through NumPy |
| tests | 30 -> 49, adding non-negative pressure, wall support, boundary clamping, determinism, acceptance-gate, and manifest-contract coverage |
| benchmarks | new `benchmarks/hydrostatic/run.py` (B1) with time-averaged profile and gates |
| docs | README, gap analysis, impact plan, and neighbour-search baseline updated to measured values |

## 9. Deliberately not done

- **Surface tension.** Choosing a formulation (CSF, Akinci, or a conservative pair force) and
  validating it is a project of its own; a half-implemented model would be worse than an
  honest gap.
- **Device-resident neighbour search.** The correct fix for the dominant cost, but it is a
  separate, reviewable change with its own performance evidence.
- **Adaptive time step.** The step is now validated and recorded; adapting it to the evolving
  maximum speed needs its own tests.
- **A LICENSE file.** Choosing a licence is the repository owner's decision.
- **Hydrostatic initialisation.** The B1 result depends on time-averaging because a
  uniform-density lattice is not in discrete equilibrium. Fixing the initialisation would
  tighten B1 further and should precede a resolution study.
