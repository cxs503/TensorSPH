# Engineering review, 2026-10

This document records the measurements that motivated version 0.2.0. Every number below was
produced by running the code in this repository; the commands are given so they can be
re-run.

## 1. How the review was done

```bash
python -m venv .venv && .venv/bin/pip install -e ".[test]"
.venv/bin/python -m pytest -q                       # 30 tests before the fix
.venv/bin/python examples/droplet_impact_2d/run.py --steps 100
.venv/bin/python benchmarks/neighbor_search/compare.py --particles 1000
.venv/bin/python benchmarks/neighbor_search/compare_rhs.py --sizes 256,512,1024
```

Plus a 4600-step version of the impact case (46 s CPU) and ad-hoc probes of the initial
state, which are reproduced as the checks below.

## 2. Finding: the free surface produced tensile pressure

At `t = 0`, before a single integration step:

```
rho:       580 – 1000 kg/m^3        (42 % density deficit at the free surface)
pressure:  min -55.9 kPa, max -21 Pa, 100 % of particles negative
|acc|:     max 4405 m/s^2           (450 g)
```

Density summation under-counts neighbours at a free surface. The Tait law
`p = rho0 c0^2 / gamma * ((rho/rho0)^gamma - 1)` then returns a large negative pressure,
which in SPH acts as attraction. Reassembling the pressure-acceleration term outside the
repository with `p` clamped at zero reduced the maximum initial acceleration from
**4405 m/s^2 to 0**, i.e. the entire initial motion was spurious.

Consequences over 4600 steps (t = 0.092 s):

| metric | measured | physical expectation |
|---|---|---|
| nearest-neighbour distance | mean 0.0090 m, 70.6 % below dx/2, min 0.0 | ~dx = 0.025 m |
| `rho_max` | 1193 kg/m^3 (+19 %) | < 1 % for WCSPH |
| max speed | 22.5 m/s | 0.9 m/s free fall |
| kinetic energy | 2373 J | ~12 J available from the drop's potential energy |

Snapshot images show the lattice disintegrating by t = 0.01 s. The run *succeeded*: no
non-finite values, and the acoustic Courant number never exceeded 0.026.

## 3. Finding: the default case never reached the pool

`dt = 2e-5 s` with `steps = 500` covers 0.01 s, during which the drop falls 0.49 mm. The
discretised gap between the drop's lowest row (y = 0.415) and the pool surface (y = 0.3375)
is 0.0775 m, i.e. about 0.13 s of free fall — roughly 6500 steps. The "first milestone" case
therefore never performed an impact at default settings.

The time step was also 24x smaller than the acoustic limit required
(`0.3 h / c0 = 4.9e-4 s`).

## 4. Finding: the coordinate clamp was not a boundary condition

```python
pos[:, 1].clamp_(min=0.5*dx, max=pool_depth + 2*drop_radius)   # ceiling = 0.55 m
```

The drop's nominal top is `drop_center_y + drop_radius = 0.59 m`, so the ceiling amputated
part of the drop: 6 particles started above it and were teleported down on the first step.

Measured with `benchmarks/hydrostatic/run.py --seconds 4`:

| boundary | interior pressure error | residual max speed | particles clamped |
|---|---|---|---|
| coordinate clamp | **26.7 %** | 21.1 m/s | 1955 |
| static wall particles | **0.63 %** | 0.055 m/s | 0 |

Measured at version 0.2.0. The viscosity correction in section 11 moves the
wall-particle figure to 1.09 %; the comparison against the clamp stands.

Clamping positions without touching velocity also injects and removes momentum arbitrarily,
and coincident particles appeared in the static pool (minimum pair separation 0.000 dx).

The difference also shows up on the impact case. With `boundary="wall"` the default 750-step
run measures 2.2 % density compression, Mach 0.075, and zero clamped particles. The same
case with `boundary="clamp"` violates its own gates within 100 steps (5.1 % density
compression, Mach 0.162), which is why the clamp is retained only as an explicit, documented
regression baseline.

## 5. Finding: the manifest did not implement its own contract

`docs/algorithm-gap-analysis.md` required source revision, Python/PyTorch versions, three
separate statuses, and per-criterion thresholds. The manifest contained
`case/status/device/initial_particle_count/config/notes`. Documentation described a contract
that the code did not implement.

## 6. Finding: dependency coupling to NumPy's C ABI

`run()` called `pos.cpu().numpy()`. With `torch==2.2.2` and NumPy 2.x this raises
`RuntimeError: Numpy is not available` and two tests fail. Snapshots now hold tensors and
plots use `.tolist()`, so the solver no longer touches NumPy's ABI; the suite passes with
both NumPy 1.26 and 2.4.

## 7. Finding: dead configuration surface

- `make_particles` returned a `fixed` mask that `run` unpacked and never used.
- `Config.seed` plus `torch.manual_seed` did nothing: the case is a deterministic lattice
  with no stochastic step. The seed was removed rather than left as a misleading knob.
- `docs/` still listed the neighbour search as an open P1 item after it had been merged, and
  the manifest notes still described all-pairs interactions as the active implementation.

## 8. What was changed in 0.2.0

| area | change |
|---|---|
| EOS | `tait_pressure` clamps at zero; documented as a free-surface treatment, not capillary physics |
| time step | default 4e-4 s; `validate_config` rejects steps above `max_courant`; `suggested_dt` exposes the limit |
| boundary | `wall_lattice` static particles with Adami pressure extrapolation and Tait-consistent density; free-slip viscosity; `boundary_box` derives the ceiling from the drop geometry |
| acceptance | `evaluate_acceptance` + `SimulationUnstableError`; five numerical criteria recorded per run |
| manifest | solver revision, environment, three statuses, per-criterion measured/threshold/result, derived quantities |
| diagnostics | added `mach_number`; plot subsamples long runs and no longer converts through NumPy |
| tests | 30 -> 49, adding non-negative pressure, wall support, boundary clamping, determinism, acceptance-gate, and manifest-contract coverage |
| benchmarks | new `benchmarks/hydrostatic/run.py` (B1) with time-averaged profile and gates |
| docs | README, gap analysis, impact plan, and neighbour-search baseline updated to measured values |

## 9. Deliberately not done

- **Surface tension.** Choosing a formulation (CSF, Akinci, or a conservative pair force) and
  validating it is a project of its own; a half-implemented model would be worse than an
  honest gap.
- **Device-resident neighbour search.** The correct fix for the dominant cost, but it is a
  separate, reviewable change with its own performance evidence.
- **Adaptive time step.** The step is now validated and recorded; adapting it to the evolving
  maximum speed needs its own tests.
- **A LICENSE file.** *Done in 0.7.0:* MIT, chosen by the maintainer.
- **Hydrostatic initialisation.** The B1 result depends on time-averaging because a
  uniform-density lattice is not in discrete equilibrium. Fixing the initialisation would
  tighten B1 further and should precede a resolution study.

## 10. Follow-up: 0.3.0 measurements

### 10.1 Neighbour search (host round-trip removed)

The 0.2.0 note that "pair construction is 83 % of the step" was the top
performance item. The search was rewritten to stay on the device and the offset
loop was batched into one `searchsorted` pass. Measured on two CPU cores,
uniform random points, `cutoff = 0.1`, best of 3, all implementations returning
the identical pair set:

| particles | brute force | host binning | vectorized | vs host |
|---|---|---|---|---|
| 400 | 2.8 ms | 4.9 ms | 1.5 ms | 3.2x |
| 1 000 | 16.4 ms | 27.3 ms | 5.5 ms | 4.9x |
| 2 000 | 66.0 ms | 96.0 ms | 17.2 ms | 5.6x |
| 5 000 | 641.2 ms | 602.3 ms | 120.0 ms | 5.0x |
| 2 000 (3-D) | 104.8 ms | 47.9 ms | 12.4 ms | 3.9x |

The previous implementation was *slower than brute force* at 1000 particles
(0.85x). It is now 3.0x faster.

### 10.2 Verlet skin

Particles move 0.4 mm per step against a 65 mm cell, so rebuilding every step is
wasted. Measured on the impact case (608 fluid + 291 wall particles, 750 steps):

| skin | step time | rebuilds | steps per rebuild | final kinetic energy |
|---|---|---|---|---|
| 0 | 7.50 ms | 750 | 1 | 15.607620 |
| 0.25 h | 4.35 ms | 66 | 11 | 15.607620 |
| 0.5 h | 4.97 ms | 34 | 22 | 15.607620 |
| 1.0 h | 5.84 ms | 17 | 44 | 15.607620 |

The kinetic energy is identical to six digits, so reuse changes only the cost.
A larger skin saves rebuilds but inflates the list that every force operator
walks; 0.25 h is the measured optimum. The whole 750-step run, including
artifact writing and plotting, went from 14.2 s to 5.2 s (2.8x); the solver step
alone went from 7.50 ms to 4.35 ms (1.72x).

### 10.3 Hydrostatic initialisation: hypothesis tested, not confirmed

Assigning masses from `rho(y) = rho0 (1 + rho0 g (H-y)/B)^(1/gamma)` puts the
pool in discrete equilibrium at `t = 0`: the initial profile error drops from
100 % to 5 % and the initial acceleration deviation from `g` to 0.05 m/s^2.

It does **not** improve the B1 result:

| initialisation | interior error | surface band | mass |
|---|---|---|---|
| uniform (default) | 0.63 % | -40.7 % | 350.00 kg |
| hydrostatic | 1.16 % | -26.4 % | 351.48 kg |

(0.3.0 numbers, measured with the then-current half-strength viscosity; at 0.4.0
the uniform case is 1.09 % and the conclusion — no improvement from the
hydrostatic start — is unchanged.)

The reason the startup transient does not matter is that the residual error is
not a transient: with free-slip walls and `nu = 0.01`, the sloshing mode has a
damping time `H^2/nu = 12 s`, so a 4 s run sits inside the same oscillation no
matter how it was started. The flag is shipped (it halves the free-surface band
error and gives a well-defined restart state) but is **off by default**, and this
negative result is documented rather than presented as a fix.

### 10.4 Dam break

A second verification case, `benchmarks/dam_break/run.py`, measures the
leading-edge trajectory `Z/a` against `tau = t sqrt(2 g / a)` at two spacings:

| `dx` | particles | steps | wall clock | Mach | compression | escapes |
|---|---|---|---|---|---|---|
| 0.02 | 200 | 2 564 | 7.3 s | 0.19 | 7.4 % | 0 |
| 0.01 | 800 | 5 128 | 33.9 s | 0.20 | 5.7 % | 0 |

Relative L2 difference of `front(t)/a` over the pre-wall-impact window:
**1.68 %**. The front stays below the Ritter shallow-water curve
(`Z/Ritter` 0.63-0.77), which is expected for a finite reservoir.

No experimental comparison is made. Of the three original obstacles, two were
removed in section 11 (no-slip walls, compressibility); the remaining one is
that the repository ships no digitized reference data. The gate exists, is named
after the reference, and reports `not_evaluated`.

### 10.5 Test growth

30 tests at the start of the review, 49 after 0.2.0, **63** after 0.3.0:
neighbour-search cross-checks, cache correctness, dam-break case and gate
coverage, and the hydrostatic initialisation contract.

## 11. Follow-up: 0.4.0 — a viscosity bug and a no-slip wall

### 11.1 The viscous operator applied half the requested viscosity

`Config.viscosity` was documented as a kinematic viscosity, but the discrete
operator lacked the factor 2 of the Morris et al. (1997) Laplacian:

```
laplacian(v)_i ~= 2 sum_j (m_j / rho_j) (v_i - v_j) . (-r_ij . grad_i W) / (r^2 + eta^2)
```

Measured by feeding a smooth field `u_x = sin(pi y / 2H)` (whose Laplacian is
`-k^2 u` with `k = pi/2H`) through `rhs` with gravity off and a low sound speed
so that pressure is identically zero, then dividing the acceleration by the
analytic Laplacian:

| `dx` | h/dx | applied / nominal |
|---|---|---|
| 0.04 | 1.3 | 0.500 |
| 0.02 | 1.3 | 0.500 |
| 0.01 | 1.3 | 0.500 |
| 0.02 | 1.1 | 0.493 |
| 0.02 | 1.5 | 0.496 |

The ratio is 0.500 to three decimals at every resolution: a normalization
constant, not a discretization error. With `VISCOUS_LAPLACIAN_FACTOR = 2.0`
restored the ratio is 1.000 (0.985–0.992 at h/dx away from 1.3, where the
lattice and the kernel no longer match). `test_viscosity_is_calibrated` pins it.

Every number published by 0.2.0/0.3.0 was therefore run with half the intended
viscosity. The benchmarks were re-measured; the change is a few percent on the
hydrostatic profile (0.63 % → 1.09 %), a 7 % slower dam-break front, and 13 %
less kinetic energy in the impact case.

### 11.2 No-slip walls

`Config.wall_friction` blends the tangential wall condition: 0 is the previous
free-slip behaviour, 1 extends the viscous stencil into the static wall
particles (mirror method), which imposes no slip.

Verification uses a quarter-wave shear over a *bottom-only* wall, with no side
constraints, so the analytic result applies:

```
u(y,0) = U0 sin(pi y / 2H)   ->   u(y,t) = U0 sin(pi y/2H) exp(-nu (pi/2H)^2 t)
```

| `dx` | friction | measured rate | analytic | ratio | KE left after 0.25 s |
|---|---|---|---|---|---|
| 0.02 | 0 (free slip) | no comparable damping | 3.084 1/s | — | 84 % |
| 0.02 | 1 (no slip) | 2.587 1/s | 3.084 1/s | 0.84 | 28 % |
| 0.01 | 1 (no slip) | 2.818 1/s | 3.084 1/s | 0.91 | 25 % |

The no-slip boundary reproduces the analytic decay and converges towards it
under refinement. Free slip imposes no tangential wall stress, so it leaves 84 %
of the kinetic energy where no slip leaves 28 %; the residual 16 % is the
solver's own numerical dissipation, not the boundary model.

Two earlier attempts at this measurement were wrong and are worth recording,
because both looked like solver bugs:

- a closed box with a *uniform* tangential velocity is not a shear flow — the
  fluid piles into the side wall and pressure grows from 0 to 1 kPa;
- leaving the clamp active on the sides makes the different rows translate by
  different amounts, the clamp then brakes them, and kinetic energy *grows* by
  a factor of 3 before the run is over.

Both were test-geometry artefacts, not solver defects. Diagnostic that settled
it: the viscous power `sum_i m_i v_i . a_visc,i` was negative (dissipative) at
every step, while the pressure power was positive.

### 11.3 Dam break: three-level ladder and compressibility

| `dx` | particles | front L2 vs next level |
|---|---|---|
| 0.04 | 50 | 2.58 % |
| 0.02 | 200 | 1.31 % |
| 0.01 | 800 | — |

Observed order `p = log2(2.58 / 1.31) = 0.96`, i.e. first order as expected from
semi-implicit Euler with a first-order boundary.

Sound-speed sweep at `dx = 0.01`: the front moves 0.034 % between
`c0` = 25 and 40 m/s and 0.019 % between 40 and 60 m/s. The observable is
therefore converged with respect to compressibility, which removes
compressibility as a blocker for an experimental comparison. What remains is
data provenance: no digitized Martin & Moyce table is bundled.
