## ① The open branch this unit works on

`docs/xval_projection_laplace_horizon_instability.md` left the dynamic arm of the anchor as an honest
FAIL: with the adjoint-consistent projection pair the drop does not come to rest — spurious current
`0.0717 -> 0.286 -> 0.4543 v_ref` at steps 10 / 120 / 180 (`3 / 12 / 18 t_sigma`) at `R/dx = 12`,
divergence at step 181. `docs/xval_projection_laplace_lattice_health.md` rejected the *lattice broke*
branch (no breakage rule fires at `R/dx = 16`), leaving *traction mis-projection*. The repo already
carries the cure for that branch — `relax_projection_balanced` splits the discrete CSF traction with
the projection's own operator into a discrete gradient (annihilated exactly) plus a remainder — but it
had been validated to **50 steps** only (`docs/xval_projection_laplace_wellbalanced.md`).

## ② What this unit did

1. **Instrumented the balanced arm.** `relax_projection_balanced` gained `stability_report` (default
   `False`), symmetric with `relax_projection_consistent`: a `lattice` block per sample (`nn_min`,
   `pair_min/dx`, colour bounds, `kappa R`, `|grad c| dx`, `a/a_ref`) and, on the breaking step, the
   entry-state finiteness flags plus the same block. Off by default, so every shipped balanced record
   stays byte-reproducible.
2. **Declared the long-horizon experiment before running it** — `benchmarks/laplace_sph/run_balanced_horizon.py`,
   four arms and eight gates in `GATES_DECLARED` / `BREAK_RULES`, with a control that differs from the
   primary arm in **exactly one knob** (the split; same `R/dx`, same `nu`, same step count).
3. **Ran what the queue allowed in this unit**: a 10-step smoke of the balanced arm with the instrument
   on, and submitted the declared marches (`cj4719`, `cj4720`, `cj4721`, `cj4722`, `cj4747`). The queue
   was at ~145 jobs ahead of the last submission and **no declared arm landed inside this unit**, so the
   horizon claim is *not* made here (see ⑤).

## ⑤ Honest scope, limits, and what is *not* claimed

* **No horizon claim.** The instability the anchor reports lives at `18 t_sigma`; the only record here
  is a `2 t_sigma` smoke. `run_balanced_horizon.py` declares `MEASURED_HORIZON_STEPS = 120` and
  `TARGET_HORIZON_STEPS = 600` and the summariser reports the missing 600-step arms as a **failed gate**
  (`long_horizon_600_all_arms_present`), so no page generated from it can present a short record as the
  long one.
* **Queue debt, with IDs.** `cj4719` (`dx12`, 600 steps, balanced, `nu_f = 0.01`), `cj4720` (same,
  `nu_f = 0`), `cj4721` (same, **no split**, 200 steps, the in-harness control), `cj4722` (`R/dx = 16`,
  200 steps, balanced), `cj4747` (the two `R/dx = 8` arms, 120 steps, 6 threads). All five were still
  `queued` at the end of this unit (~145 jobs ahead). Re-running the arms is not a re-derivation:
  ```bash
  PYTHONPATH=src python benchmarks/laplace_sph/run_balanced_horizon.py --job dx8_h120_bal_nu01 --threads 6
  PYTHONPATH=src python benchmarks/laplace_sph/run_balanced_horizon.py --job dx8_h120_ctl_nu01 --threads 6
  PYTHONPATH=src python benchmarks/laplace_sph/run_balanced_horizon.py --summarize --figure
  ```
* The smoke is `R/dx = 8`, `nu_f = 0`, 10 steps: it exercises the instrument and the loop, it does not
  measure a decay rate, a horizon, or a resolution trend.
* Equal-density carrier, inviscid static physics, 2-D hex lattice: `sigma/R` is the only physics in the
  problem. Nothing here speaks to capillary waves, real density jumps or 3-D.
