# 砰击战役的「算得动吗」前置门：cost_probe 工具 + 本机容量实测（m16822）

**仓**: TensorSPH ｜ **类型**: 验证欠账工具化（不做物理结论）｜ **锚点**: 总账外新缺口
**性质**: **不是**验收、不产生任何 `C_s` 读数；`CASE-*` 相关判据维持 **WITHHELD**

## 1. 案例与背景

`benchmarks/slamming/run.py`（战役节点 p129w1r2-n08）是入水砰击载荷的验证面，判据写得很清楚
（`C_s,max` vs Wagner `π²/tanβ` ≤ 15 %、压力形状 L2、噪声、力峰值观测阶、质量守恒）。
但**SPH 侧一条 admissibility 读数都没有**：验证账本对 `benchmarks/slamming/` 至今只能给
目录级豁免（`waivers.json`，2026-11-07 m14849 登记，理由「harness only, no committed artifact」）。

`docs/slamming_evidence_blocker_m14940.md` 已把障碍量化为**成本壁垒**：`dx = 2 mm` 单算例
≈ 110 s 以上，且预撞阶段每步成本上涨 20–28×，于是「递交集群 → 等执行 → 提交工件」这条链
在本地 120 s shell 窗口内根本走不完。

**本单要回答的问题**：在动手跑战役之前，怎么**先**知道「这台机器现在能不能在预算内跑完一个算例」，
而不是launch 完再等超时。

## 2. 怎么做的

1. 新增 `benchmarks/slamming/cost_probe.py`：以 `SlammingImpact` 本体跑**显式指定步数**的小探针
   （把观测窗口缩到刚好等于请求步数），测量每条：`n_fluid` / `n_wall` / `dt` / 探针步数 / 墙钟 /
   每步均值，并把**战役算例**（`t_end = 2 c_end tanβ/(πV)`，与 `run.py` 同一公式）的
   投影墙钟 = 每步均值 × 战役步数，按 `--budget`（默认 120 s）给出 `affordable` 布尔判定与
   `verdict` 文案。投影标注为**下界外推**（m14940 实测每步成本在预撞阶段上升），JSON 里写明。
2. 探针**不记录 `C_s`**：它没有物理判据，因此不能被评分，也不进入账本（避免把「能跑」误当「对」）。
3. 新增 `tests/test_slamming_cost_probe.py`：用**假求解器**（固定 `dt`=1.3e-5、固定步数 445、
   `run()` 零工作量）钉住投影算术与判定逻辑，含**负控**（0.01 s/step × 445 步必须判 NOT affordable）
   与**判定翻转**对照（预算放大后同一记录必须判 affordable）；另有一条锚点测试：
   `steps × dt == 2 c_end tanβ/(πV)`（5 % 内）。
4. 本机容量实测：直接对 `dx = 4 mm`（N≈3 000）跑 12 步探针，**115 s 内未返回**（本单命令被
   超时收割），据此判定本机当前不具备跑战役的容量。

## 3. 结果

| 量 | 值 | 来源 |
|---|---|---|
| 探针工具 | `benchmarks/slamming/cost_probe.py` | 本单新增 |
| 投影公式 | `per_step × 2 c_end tanβ/(πV) / dt` | 与 `run.py` 同一 `t_end` |
| 判定 | `affordable = projected_wall_s ≤ budget` | `cost_probe.main` |
| 本机 12 步 @ `dx = 4 mm` | **> 115 s 未返回** | 本单实测（命令被超时收割，`runs/` 无产物） |
| 会话期本机负载 | load15 60 → 134（nproc 128） | `/proc/loadavg` 采样 |

**没有产出的东西（诚实登记）**：`runs/m16822_slamming_cost/probe_dx4.json` 未生成 =
本单**没有**任何 admissible 的 `C_s` 读数，`benchmarks/slamming` 维持豁免状态，账本条目不变。

## 4. 结果图

## 5. 注意点（局限与适用域）

* 探针给出的是**下界**：均值步成本忽略了 m14940 观察到的预撞阶段 20–28× 上升，因此
  `affordable = true` 只是必要条件，不是充分条件。
* `dx = 4 mm` 的 12 步探针在 115 s 内未返回，与 m14940 记录的 0.081 s/step 差两个数量级；
  两种解释都未区分：**(a)** 会话期本机被 134 负载压满（外部进程，非本单），**(b)** 预撞段成本
  机制在这些步里已被触发。区分方法是把 `--steps` 取 2/4/8 并记录每步墙钟——本单**没有做**
  （预算耗尽），故这只是**待判**，不是结论。
* 因此本单的结论严格限于工具与算术：`cost_probe` + 其测试可复用，物理判据一律未动。

## 6. 误差判定

本单不存在被测量的物理量，唯一可比数字是投影恒等式（`projected == per_step × steps`，测试逐位相等）
与战役 `t_end` 锚（`steps × dt` vs 解析式，5 % 内）。**「是否 < 3 %」：不适用——没有基准量。**
如实声明：砰击 `C_s` 判据 = **WITHHELD / not_run**，本单不升级、不粉饰。
