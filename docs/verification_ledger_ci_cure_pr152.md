# PR #152 CI cure: ledger coverage + repo-wide lint gate

**Branch**: `agent/m3665` (PR #152) ｜ **Worktree**: `m4133` ｜ **Commit**: ledger coverage + ruff gate
**Artifacts**: `benchmarks/verification_ledger/ledger.json`, `docs/verification_ledger.md` (both regenerated, no hand edits)
**Touched source**: `benchmarks/verification_ledger/build_ledger.py` (`coverage_claims()`), `pyproject.toml` (ruff config),

## 1. Case: what was red, and why

PR #152 was red in all three matrix jobs (`pytest (3.10/3.11/3.12)`). The workflow runs, in order,
`ruff check .`, `pytest -q`, then a tiny end-to-end case, inside each job. Two *inherited* defects
reproduce identically on every Python version, so the matrix fails uniformly:

| # | Defect | Reproduced on |
|---|--------|---------------|
| A | `tests/test_verification_ledger.py` fails 4/20 tests: 5 evidence files landed by the m3087 / m3114 / m3151 / m3188 / m3432 merges were never registered as ledger claims, so `unregistered_artifact` findings clip the coverage test and the committed `ledger.json` / `docs/verification_ledger.md` no longer equal a fresh regeneration (anti-drift test) | **pure `origin/main` (733f182)** — i.e. inherited, not introduced by #152 |
| B | `ruff check .` exits 1 with **100 errors** (76 × E501, 12 × F401, 8 × W292, 2 × E702, 1 × E741, 1 × E401) in files that main merged after the last lint pass — the job aborts at the lint step, before pytest even starts | **pure `origin/main` (733f182)** |

Nothing in #152's own diff (`csf_consistent.py` parameter pass-through + its verification doc) causes
either defect; #152 simply cannot go green while main is red.

## 2. Method

1. **Reproduce first, on main, not on the PR.** A detached worktree of `origin/main` was run with the
   same commands as CI; A and B both reproduce there. Only then was the PR branch merged with
   `origin/main` (clean, no conflicts) and re-run, giving exactly the same failures.
2. **Fix A by covering the evidence, not by waiving it.** `build_ledger.py` gains
   `coverage_claims()` with one claim per unregistered artifact. Every number is read from the
   artifact at generation time (`json_path` resolution), graded by the same 3 % / 15 % ladder as the
   other 16 claims, and points at an existing guarding test:

   | claim_id | artifact | reading | grade |
   |---|---|---|---|
   | `conservation.viscous_pair.closed_form` | `benchmarks/conservation/report.json` | net viscous pair force / closed form = 1 − 7e-16 | PASS |
   | `init_consistency.spurious_pressure.calibrated` | `benchmarks/init_consistency/report.json` | worst calibrated \|p_false\|/(ρ0c0²) = 6.7e-16 vs 1e-4 gate | PASS |
   | `initial_density.hex_drop.bias` | `benchmarks/initial_density_bias/report.json` | 5.883522e-3 measured vs closed-form 5.883522e-3 | PASS |
   | `lattice_equilibrium.interior_density_offset.calibrated` | `benchmarks/lattice_equilibrium/report.json` | interior \|ρ/ρ0−1\| = 5.96e-7 vs 1e-4 gate | PASS |
   | `laplace_pressure_closure.relaxed_tail.layers2` | `benchmarks/laplace_pressure_closure/raw/relax_ladder.json` | relaxed tail Δp = 391.8 Pa vs 360 Pa (+8.83 %) | MARGINAL |

   `waivers.json` was **not** extended — waiving five real, gate-bearing evidence files would have
   removed the finding without removing the blind spot.
3. **Fix B at the lint surface, not at the code.** The E501 cluster lives in documentation
   renderers (`benchmarks/**/make_doc.py`), whose string literals are Markdown table rows: reflowing
   them would change generated documents, so they are declared in
   `[tool.ruff.lint.per-file-ignores]`. `.scratch/` (another mission's scratch area) is excluded.
   The 12 remaining mechanical defects were fixed automatically (`ruff check --fix`): missing final
   newlines and unused imports. `src/tensorsph/__init__.py` re-exports the eight `initial_density`
   helpers — they are now declared in `__all__` instead of deleted, because downstream code imports
   them from the package root. Two single-line `# noqa` (E741 in a benchmark loop variable, E501 in a
   f-string table row) close the rest.
4. Ledger JSON and Markdown were regenerated by the builder itself (`build_ledger.py`), never edited.

## 4. Attention points / scope

* **Local environment trap.** `site-packages/__editable__.tensorsph-0.8.0.pth` on this host points at
  *another* worktree (`work/m4111/src`), so a plain `python -m pytest` in this worktree tests the
  wrong library and raises `ModuleNotFoundError: tensorsph.lattice_consistency` at collection. Every
  measurement above was taken with `PYTHONPATH=<worktree>/src`, which reproduces CI's
  `pip install -e .` import order.
* **Scope of B.** Because main is red at the lint step, the lint cure necessarily touches files
  outside #152's subject (`pyproject.toml`, `src/tensorsph/__init__.py`, two benchmark files). The
  changes are style/declaration only — no numerical code path is modified, and the only behavioural
  side effect is that `initial_density` helpers become explicit package exports.
* **Not addressed here.** Three simulation tests fail on this loong64 host under heavy CPU
  contention (other agents' jobs); they are outside the ledger/lint surface and were not triaged to
  root cause within this mission's budget — see §6, honest status.
* The ledger tolerances are the platform ladder (3 % paper grade, 15 % acceptability); the MARGINAL
  closure claim stays MARGINAL, it is not promoted.
