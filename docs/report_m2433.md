## 1. 案例介绍

### 1.1 物理与工程背景

TensorSPH 是船舶总体性能平台中基于光滑粒子流体动力学（SPH）的求解模块，覆盖以下学科方向：

- **入水砰击**（slamming）：Wagner 理论锚、δ-SPH 密度扩散、MLS 密度重整化
- **黏性流动**：Poiseuille 通道验证（镜像/幽灵粒子无滑移壁面边界）
- **规则波造波**：WCSPH 求解器 + 活塞造波 + 海绵层 + 波高计
- **自由面流动**：溃坝（dam break）、Taylor-Green 涡、Couette 流等基准

## 2. 怎么做的

### 2.1 方法论

本任务是一次**仓库级代码审计与缺陷诊断**，而非数值计算任务。方法论如下：

1. **全只读扫描**：不修改任何业务代码，仅读取和分析

3. **历史报告挖掘**：通过 API 获取已有报告的「局限/待办」节，识别反复出现的失败模式

5. **根因分析**：对反复失败的验证案例进行深层原因诊断

### 5.2 仓库级注意事项

从工作树现有证据可归纳以下通用注意事项：

1. **分辨率是 SPH 验证的第一瓶颈**：
   - Poiseuille 通道在 H/dx=8 时即可达 <0.5% 误差
   - 波 flume 在 H/dx=2.6 时误差达 65.5%，需提升至 H/dx≥6.4
   - **建议**：所有新 benchmark 须先做分辨率阶梯

2. **解析解验证是信任基础**：
   - 砰击问题的 Wagner 理论锚在机器精度通过
   - **建议**：每个新求解器必须先过解析解验证再进入网格收敛

3. **集群资源是端到端验证的瓶颈**：
   - 波 flume 验证因集群排队（>2h）未能完成端到端闭环
   - **建议**：关键 benchmark 应预留集群时间窗口
