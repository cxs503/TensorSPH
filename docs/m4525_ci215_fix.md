## 4. 顺带修掉的一个真红测（pytest 步会撞上）

`tests/test_laplace_pressure_jump.py::test_figure_exists` 断言仓库里存在
`benchmarks/laplace_pressure_jump/laplace_pressure_jump.png`（>10 kB）。该 PNG 是
`run.py:make_figure` 的**可再生工件**，交付门禁会滤掉二进制，因此干净检出必红：

```
$ python -m pytest tests/test_laplace_pressure_jump.py -x -q     # 修复前
1 failed, 12 passed, 1 xfailed
FAILED tests/test_laplace_pressure_jump.py::test_figure_exists - assert (False)
```

改为 `test_figure_renders_from_the_committed_report`：以已提交的
`validation_report.json` 驱动 `run.make_figure(report, out_dir=tmp_path)`，断言
写出 PNG 且 >10 kB、PNG 魔数正确 —— 校验的是「数字还能画出来」，而不是「某个二进制在不在库里」。

```
$ python -m pytest tests/test_laplace_pressure_jump.py -q         # 修复后
14 passed, 1 xfailed
```

## 6. 未解决 / 诚实标注

`tests/test_initial_density_calibration.py::test_make_particles_calibration_flag_is_off_by_default_and_scales_mass`
当前在 main 上失败，来自**最近合入的 #231（m4131, commit `2ce2f73`）**：`Config.density_calibration`
默认值被改为真，而该测试（m3209 时代）断言「默认关闭 ⇒ 质量 = rho0·dx²」。
`lattice_mass_unit` 在 `density_calibration=False` 时确实返回 `rho0*dx*dx`，所以这是
**默认值契约冲突**，不是数值误差。修它等于给初始质量校准定一个物理默认值，
属于 m4131/m3209 的学科决定，本单不动（避免掩盖或回退物理默认）。
它会让 `Run unit and smoke tests` 这一步继续红，需要单独一单裁决。
