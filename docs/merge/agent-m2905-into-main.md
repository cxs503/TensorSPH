## 2. The four conflicts

Both sides created a *reference audit* of the B2 dam-break validation target
(the bundled "Martin & Moyce (1952)" table). The two audits are not duplicates:

* **`main` side (layer A)** — abscissa-lattice / ordinate-quantum audit of the
  bundled table, the analytic Ritter reference and its `Z/a = 2 tau` identity,
  a `wall_friction × dx` sweep of the dimensionless front coefficient
  `c = d(Z/a)/d tau`, and three figures.
* **`agent/m2905` side (layer B)** — structure and kinematics of *both*
  independent transcriptions of the same figure, the cross-source spread
  (0.851 in `Z/a` = 17× the claimed ±0.05), three explicit gates, and the
  verdict `physical_validation = withheld`; plus the resolution ladder measured
  against both references (`reference_ladder.py/json/png`, no conflict).

Resolution rule used for all four files: **semantic union** — every function,
every test, every measured number of both sides survives; where both sides
described the same field, the union keeps the wider wording and adds the
missing text rather than choosing one.

| file | conflict | resolution |
|---|---|---|
| `benchmarks/dam_break/reference_audit.py` | add/add | one module with both layers: layer A functions (`audit_table`, `ritter_profile`, `ritter_checks`, `fit_window`, `front_coefficient`, `run_rung`, `targets`, `make_figures`) **and** layer B functions (`_interp`, `load_bundled`, `load_crosscheck`, `_claimed_uncertainty`, `grid_stats`, `cross_source_spread`, `evaluate`). ## 3. Content-preservation checks (nothing silently dropped)

Programmatic, against the two pre-merge blobs of `reference_audit.json`:

```
missing from union vs origin/main:  set()      # layer A keys, incl. solver block
missing from union vs agent/m2905:  set()      # layer B keys
tables / grid_stats / cross_source_spread / gates / verdict:  IDENTICAL (value by value)

table_audit: identical to origin/main (incl. grade_reason + smoothness_note)
ritter / table_slope / window_tau / solver / geometry: identical
```

Two of those keys were **only** present in a committed artifact and were not
emitted by the pre-merge code (`solver`, `table_audit.smoothness_note`), i.e.
main's artifact had already drifted from main's code. The merge makes the code
emit both — `solver_config()` reads `DamBreakConfig`, `smoothness_note` is
formatted from the measured second-difference RMS — so the merged artifact is
reproducible from the merged code instead of being a hand-maintained file.

Surface-level (non-semantic) normalisations, all documented:

1. `tables.*.path` and the ladder's `references.*.path` / `plot_path` held
   `/root/tp-agent/work/m2905/...` (the worktree that produced them). They are
   now repo-relative (`benchmarks/dam_break/...`); no number changed.
2. Two writers rendered the same document path. The merge keeps **one**
   generator (`make_audit_doc.py`, now rendering both layers);
   `make_reference_audit_doc.py` is kept as a delegating alias so the old
   command line still produces the same document. No rendered number is lost:
   every number layer B rendered lives in `reference_audit.json`.
3. `.scratch/probe.py` (added by `agent/m2905`) is a 5-line REPL fragment with
   an undefined name (`cfg_dt`). It makes the repository's CI lint gate
   (`python -m ruff check .`, `W`/`E`/`F`) fail, so it is dropped from the
   tree — an explicit deletion, recorded here, not a silent one. The rest of
   `agent/m2905`'s `.scratch/` additions (`sim040.json`) are kept unchanged.
